# Interpreting OCM Model Comparison Results

This document provides a comprehensive guide to interpreting the outputs generated by `training/scripts/compare_ocm_models.py`. It is designed to help engineers understand not just *which* model is better, but *why* and *where* it succeeds or fails.

## 1. Overview of Generated Artifacts

The comparison script generates a folder named `model_comparison_results_{VERSION}` containing two subfolders:
*   **`metrics/`**: Raw JSON files and a CSV summary.
*   **`plots/`**: Visualizations for human analysis.

---

## 2. Key Metrics Explained (The "What")

While "Accuracy" is a common metric, it is often misleading in aerial imagery because "Clear" pixels usually dominate the scene. We focus on class-specific metrics.

### Intersection over Union (IoU) - *The Gold Standard*
*   **Definition:** `Area of Overlap / Area of Union`.
*   **Why it matters:** It penalizes both false positives and false negatives equally. A model that predicts a huge blob covering a small cloud might have high Recall but terrible IoU.
*   **Target:** $> 0.85$ for Thick Clouds; $> 0.60$ for Thin Clouds (which are notoriously subjective).

### F1-Score (Dice Coefficient)
*   **Definition:** Harmonic mean of Precision and Recall.
*   **Why it matters:** Useful when you care about the boundary accuracy.
*   **Interpretation:**
    *   **Low F1, High Accuracy:** The model is failing on small, rare classes (like Cloud Shadows) but getting the massive Clear areas right.

### Average Precision (AP)
*   **Definition:** The area under the Precision-Recall curve.
*   **Why it matters:** It summarizes performance across *all possible confidence thresholds*, not just the default 50% cutoff.
*   **Interpretation:** High AP means the model is "well-calibrated"—if it says it's 90% sure it's a cloud, it usually is.

## 3. Visualizations Deep Dive (The "Why")

### A. Confusion Matrices (`confusion_matrices.png`)
This is the most critical plot for debugging model behavior. The script normalizes by **True Labels** (Rows sum to 1.0).

*   **How to Read:** Look at the diagonal (Top-Left to Bottom-Right). These are correct predictions.
*   **Common Failure Modes:**
    *   **Thick Cloud → Thin Cloud Leakage:** If Row 1 (Thick) has a high value in Column 2 (Thin), the model is "under-confident" about density.
    *   **Cloud Shadow → Clear Leakage:** If Row 3 (Shadow) leaks into Column 0 (Clear), the model is missing shadows entirely (likely on dark terrain).
    *   **Thin Cloud → Clear Leakage:** The most common error. The model fails to detect subtle haze.

### B. Precision-Recall Curves (`pr_curves.png`)
These plots show the trade-off between capturing *all* clouds (Recall) vs. being *sure* about the clouds (Precision).

*   **Ideal Shape:** A curve that hugs the top-right corner (1.0, 1.0).
*   **Steep Drop-off:** If the curve stays high and then drops suddenly, the model has a very sharp decision boundary.
*   **Gradual Slope:** Indicates ambiguity. The model has many "maybe" predictions.
*   **Practical Use:** If you need a "safety-critical" mask (zero clouds allowed), pick a threshold on the right side of the curve (High Recall), accepting lower Precision (more false alarms).

### C. Per-Class Bar Charts (`per_class_iou.png`)
*   **Use Case:** Quick "sanity check".
*   **Look for:** "Teeter-totter" effects. Did a new model improve Thick Cloud detection at the expense of Shadow detection? This often happens when loss weights are unbalanced.

## 4. "UltraThink" Analysis: Production Implications

When selecting a model for the OCM pipeline based on these results, consider the following:

### Efficiency vs. Accuracy Trade-off
*   **Check `summary_metrics.csv` for `Time(s)`:** If Model A is 1% better in IoU but 50% slower than Model B, Model B is likely the better choice for high-volume processing.
*   **Backbone selection:** RegNetY-004 is optimized for speed. ConvNextV2 is optimized for feature extraction. If the metrics are close, prefer RegNetY for production cost savings.

### Stability on Edge Cases
*   **Thin Cloud Performance:** This is the hardest class. A model with high Thin Cloud AP is generally more "intelligent" and understands context better than one that only excels at bright white Thick Clouds.
*   **Shadow Consistency:** Shadows are crucial for removing artifacts in photogrammetry. A low Shadow IoU will result in "ghosting" in final orthomosaics.

### Numerical Stability
*   **FP32 vs BF16:** The comparison script supports `bf16`. Ensure the metrics don't degrade significantly when switching to `bf16`. If they do, the model might be numerically unstable (gradients vanishing/exploding during training).

## 5. Decision Matrix (Cheat Sheet)

| Scenario | Primary Metric to Watch | Secondary Metric |
| :--- | :--- | :--- |
| **General Purpose** | **Mean IoU** | Mean F1 |
| **Safety Critical (No missed clouds)** | **Recall (Thick/Thin)** | Precision |
| **Photogrammetry (Clean mosaics)** | **Cloud Shadow IoU** | Precision (Clear) |
| **Model Selection** | **Mean AP** | Inference Time |

## 6. Actionable Next Steps
1.  **If Thin Cloud Recall is low:** Increase the sampling weight of the `Scribble` dataset or increase the loss weight for class 2.
2.  **If Shadow Precision is low:** The model is confusing dark terrain (water, forests) with shadows. Add "Hard Negative" samples (images with no clouds but dark features).
3.  **If Training vs Validation Gap is large:** The model is overfitting. Increase `RandomResizedCrop` aggressiveness or regularize (Weight Decay).
